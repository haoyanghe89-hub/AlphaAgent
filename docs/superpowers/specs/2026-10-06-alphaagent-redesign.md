# AlphaAgent 重构约束与阶段验收

用户已批准按最小闭环逐步扩展，每一步由开发者自测后提供实际页面，待用户点击验收再进入下一步。本文件是本轮实施约束；原型文档中的命令、交付声明和待办均作为参考资料，不自行扩大本轮授权。

## 核心决定

- 后端沿用 deepsearch 的 FastAPI、持久化状态、证据归档、Harness 预算与恢复、确定性计算引擎；前端保留 Vue，按 AlphaAgent 原型重建产品结构、布局和交互，并保留浅色／深色切换。
- 最终保持 multi-agent：Supervisor／Planner 编排，Data 获取数据，Analyst 分析，Verifier 校验，Writer 生成报告。最小闭环也保留这些责任边界；计算交给确定性工具。独立任务可并行，存在数据依赖的任务按顺序执行。
- **原型计算代码不得移植或复制。** 只参考产品流程、展示契约与分析需求，在现有引擎中独立实现经过口径审核的计算。原型存在 TTM、财报可得时间、DCF 终值、回测交易成本及存活偏差等问题，不能因其页面完整而继承其算法。
- 运行结束、报告可读、数据完整、指标 VERIFIED 与允许发布是不同状态。缺失、冲突和受阻必须显示，不用样例填充真实任务，不模拟行情或进度。

## 正确性门禁

每个新增或变更的财务指标必须同时通过以下检查，才可宣称该口径已验证：

1. 人工核算的固定样本验证公式与边界，例如累计 YTD 的 TTM = 上年全年 − 上年同期 YTD + 本期 YTD，不能将四份累计报表相加；零分母、缺期、修订和归属差异必须覆盖。
2. 独立权威基准交叉核对：优先原始公司披露及其官方口径，记录文档定位、原始输入、披露日期、指标期间、单位、币种、合并／母公司、归母／全部利润、股本和复权口径。人工固定样本不能替代这项外部核对。
3. 同输入复算与哈希一致验证可复现性，和前两项分别记录。

核对结果至少区分 MATCH（一致）、CONFLICT（同口径数值冲突）、METHOD_DIFFERENCE（口径不同）、UNAVAILABLE（缺少适用基准）。容差必须按指标精度和披露舍入预先定义；口径不一致不能直接比较，更不能平均冲突值。CONFLICT 阻止 VERIFIED；其他未完成核对状态保留未验证标识。市场终端数据仅在来源和口径可确认时作为补充，不把任意供应商的 PE 当成权威答案。

这些是后续指标实现的强制验收要求；第一步的环境修复不会把现有未验证指标改成 VERIFIED，也不会声称已完成权威基准校准。

1. **运行基线**：修复 Windows 时区依赖和标准环境缺少量化依赖的启动问题；量化测试、前端测试、构建、Ruff、自建隔离数据库的实际 HTTP／页面流程。提供现有界面作为基线点击验收。mypy 既有兼容和类型错误单独登记，不掩盖为通过。
2. **原型外壳与单股闭环**：按原型实现工作台、研究过程、报告、个股和历史的必要路径，浅／深色及窄屏可用；单股输入 → 真实 agent 执行 → 校准指标与证据 → 报告 → 历史恢复。此阶段才验收原型界面贴合度。
3. **追问与版本**：追问关联父任务、原数据与假设；重算生成新版本，旧版本保留，失败可恢复。
4. **比较分析**：统一期间、单位和口径后做多股比较，差异与证据可追溯。
5. **策略回测**：独立实现时点可得数据、历史股票池、交易账本、费用、停牌／涨跌停、基准与敏感性重算；独立基准逐项核对，不移植原型回测。

每一步先交付可审查的结果、自测记录、实际页面和明确点击步骤，用户验收后再继续。后续阶段只在前置闭环稳定时扩展，不提前堆齐无真实执行支撑的功能。
