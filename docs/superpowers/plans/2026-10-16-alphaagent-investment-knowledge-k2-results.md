# K2 方法规则提炼、审核与发布验收

日期：2026-10-16。范围沿用已批准的知识体系方案；本阶段实现参考规则层，不提前声明 K3 路线可执行或 K4 工作台报告接入。

## 实际结果

- 本地已发布 24 条固定版本规则，覆盖筛选、入场、持有、退出、风险、容量、估值、市场环境八类；来自八个来源族、十一份已封存资料。
- 每条保存作者主张、系统改写、必要输入、适用条件、检查步骤、反例、禁止推断、参数出处和精确正文字符区间。
- 作者数值使用 `AUTHOR_ORIGINAL / SOURCE_MARKET_ONLY`；系统数值提案使用 `SYSTEM_PROPOSAL / UNVALIDATED_PROPOSAL`。当前种子没有新增 A 股交易阈值。IBD 的原始数值不能自动成为本地执行参数。
- 所有规则均为 `REFERENCE_ONLY / UNVALIDATED`。发布表示可供研究引用，不能据此声称盈利、给出未经工具核算的交易数量或推导下一交易日方向。

## 原文与模型审核

候选由 Codex 阅读已取得正文后形成，不声称读完整本投资书。`SupportReviewer` 检查原文支持和归因，`CounterexampleReviewer` 检查反例、条件及适用边界；两种职责使用项目现有 DeepSeek 模型，不是外部专家或独立效果验证。

用户在本轮明确授权把候选及对应公开原文片段发送至现有 `api.deepseek.com` 审核，并仅在本地发布通过版本。第一次网络权限升级曾被自动审批拒绝，取得上述明确授权后才继续。

真实归档共十次尝试：八次完整成功响应、一次连接未建立、一次批次契约失败。最后一批的一条响应多返回空字段；不删除字段来接受该条，而是按原契约单独重审。该失败批次其余五条按原始内容逐项严格校验，并在审核记录与开发者页标注 `VALIDATED_ITEM_FROM_FAILED_BATCH`。原失败状态、原始响应及重审均保留。

审核成功响应报告的令牌合计 36,419；含未知用量失败响应的保守计费量为 54,650，未超过 60,000 上限。连接未建立那一次的预留通过保留完整连接失败证明的结算收据释放，尝试计数不删除。超时、已响应或用量不明的请求不得据此释放预算。最大调用数仍为二十四，审核运行累计耗时在九百秒内。没有改动旧下一交易日模型协议或旧计算／回测预算门禁。

## 保存、检索和接口

新增数据库迁移 `20261016_13`，记录规则版本、审核快照、规则审核与发布／撤回事件。规则正文、模型请求、响应、失败证明和审核结果使用现有 CAS；共享归档清理和配对备份可从数据库列发现所有引用。四类新表均禁止 UPDATE / DELETE。

生命周期为 `DRAFT → REVIEWED → PUBLISHED → RETIRED`。发布必须核验同一规则版本的实际审核；撤回版本不再进入当前检索，历史查询只返回截止时已经发生的发布事件。旧版本不覆盖。

内部检索当前使用有界词法相关度、同义词扩展、周期／发布时间筛选与来源族去重，每份研究上下文最多十二条。词法分数不表示方向概率或收益，重复作者观点不计为独立证据。当前尚未建立向量索引或模型重排，不能称为已完成混合语义 RAG。

只读接口：

- `GET /api/quant/knowledge/rules`
- `GET /api/quant/knowledge/rules/search?q=买点&horizon=SWING`
- `GET /api/quant/knowledge/rules/{rule_id}/versions/{version}`
- `GET /api/quant/knowledge/reviews/{review_id}`
- `GET /api/quant/knowledge/audits/{audit_id}`

没有 HTTP 发布／撤回接口；`developer=1` 是展示开关，不授予写权限。K1 来源读取 manifest 不重写，方法发布情况以 `/rules` 为准。
