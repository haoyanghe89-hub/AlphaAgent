# AlphaAgent 下一交易日涨跌预测实验

日期：2026-10-12，Asia/Shanghai。状态：用户已要求纳入最早交付；本文是待实施方案，本轮不改业务代码。

配套：[研究设计](superpowers/specs/2026-10-12-alphaagent-decision-research-design.md)、[实施计划](superpowers/plans/2026-10-12-alphaagent-decision-research.md)、[投资方法与行业资料](alphaagent-investment-methodology-and-semiconductor-research.md)。本实验新增范围优先于旧文档中暂不做短期方向的表述；仍不提供未经校准的概率或实盘执行。

## 1. 用户要测什么

用户希望实验阶段就明确看到“明天预测涨/预测跌”，保留原因，等真实结果出现后统计准确率。实验先评估方向判断，不要求先形成可交易策略，也不以用户真实投入资金为前提。

“最开始”包含两个要求：

1. 开发顺序：P0完成必要合同和数据探测后，在P1增加N任务，先交付预测→封存→次日核对；不等P2–P7全部完成。
2. 页面顺序：取到必要数据并完成审核后，报告顶部先展示下一交易日涨跌预测及主要依据，再展示1–3个月研究。不能先无数据猜一个方向，研究完成后悄悄替换。

长期经营看好与明日下跌可以同时成立；两个期限独立输出、独立审核、独立统计。半年报、行业长期增长不能单独证明明天上涨。

## 2. 第一版固定实验协议 NEXT_SESSION_EOD_V1

### 2.1 时间、标的与封存

- 交易日历按标的交易所解析；“明天”是预测基准交易日T之后的下一市场交易日T+1，不是下一自然日。
- 主实验固定在T日20:00–20:15完成，Asia/Shanghai。用户手动触发，不创建自动化；取证/封存和模型签发均须在窗口内。具体窗口可以在实验开始前配置，修改后创建新protocol_id，不把不同预测时点混成一组。
- 取证结束记录 `evidence_sealed_at` 和输入哈希，随后预测角色只读封存快照；`issued_at >= evidence_sealed_at`，且须在20:15之前完成。后续发布的消息不能回填到原预测理由。
- 不在固定窗口的手动预测也可保存和显示，但标记EXPLORATORY，按另一时点组统计；不能替换主记录或在看到结果后选择分组。
- 首期默认固定中微公司688012.SH、北方华创002371.SZ两只作为前瞻测试篮子，开始前存成有版本名单；这是实验样本，不是推荐名单。之后增删名单须在结果出现前记录新版本，原样本不删除。
- 主记录唯一键为 `experiment_id + security_id + target_session`，一个标的一天只能有一个正式判断。首次成功签发后再试、刷新、改模型均产生辅助记录，不能选择最有利的版本参加主统计。

没有按时触发、超时、源失败、审核失败都记入计划样本清单。失败不是预测错误，但必须显示缺席比例，不能用少预测掩盖实验执行问题。

### 2.2 “涨/跌”的准确口径

主标签预测的是**T+1收盘时行情口径的涨跌方向**：

`r = (close[T+1] - exchange_reference_price[T+1]) / exchange_reference_price[T+1]`

普通交易日参考价通常是T收盘价；除权除息日参考价可能调整。因此不能把两个原始收盘价简单相减作为所有日期的标签。上交所规则说明除权息日即时行情前收盘价采用除权息参考价；深圳标的实施时分别核对其当前规则和来源字段。[上交所原始规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)

- r > 0：实际UP；r < 0：实际DOWN；r = 0：实际FLAT。按原始价格精度/Decimal计算，不从四舍五入的百分比字符串推方向，不人为设置宽容区间。
- 预测值只允许UP或DOWN。数据足够但观点冲突仍给一个方向，并标记证据支持弱；不靠“震荡/不确定”挑选容易答的样本。
- 必要行情、证券身份、交易日历或输入完整性失败时不伪造方向，记录FAILED_INPUT。它计入计划量与覆盖率，不进入已签发准确率。
- T+1全日停牌、退市无有效收盘等记UNSCORABLE，并显示数量/原因，不视为FLAT，不自动顺延到复牌日。部分时段停牌但有有效收盘可正常核对。
- 次日收盘尚未发生为PENDING；收盘已发生但尚未拿到可核验结果为PENDING_DATA，两者与失败、平盘和收益为零分开。
- 次日标签的参考价和收盘价只能在事后核对时读取；不会放入预测输入。公司行为资料不完整或两源价格冲突时暂停核对，不能猜调整因子。

这是行情方向实验，不是全收益、开盘买收盘卖收益或可执行交易胜率；原5.2门禁不变。

## 3. 模型如何产生预测与原因

初版收集可得的截至封存时点的市场/行业/个股价格、收益、波动、成交、相对强弱，以及融资/供应商资金、已发布公告与事件。资金源缺失如实标注；并非所有渠道齐备才允许运行，但价格与主体等最低数据要求不能绕过。

先由程序计算数值，LLM基于结构化输入明确选择UP/DOWN，给出：

- 1–3项支持原因及证据ID，指明为什么可能影响下一交易日。
- 至少一项主要反对理由；没有额外反证时说明观察局限，不编造事实。
- 信息尚未发生的风险，如隔夜事件、市场共同波动；不能预测未知新闻具体内容。
- 实际数据缺项、方法版本及审核记录。

Verifier审核引用、数字、时间、期限适配及无依据机构意图；Writer只能表达通过审核的方向和理由。审核失败不发布方向，记失败。签发后不能在盘中看到走势再修改主记录。

首版不展示“上涨概率70%”之类数字。证据支持强弱不是概率；预测准确率是之后观察出来的统计量。也不把长期方法卡、多个模型投票或复杂架构当作预测能力证明。

用于对照的两种模型方案固定相同标的、证据和截止时点：

1. 通用LLM直接读结构化快照，输出方向和依据。
2. 同一LLM使用有期限约束的方法卡与审核流程。

方案2为首版主实验，方案1作为有预算才启用的预注册对照；对照缺席不能减少主实验统计分母。初期不同时叠加微调、多个预测模型和大量指标搜索，以免无法知道改进来自哪里。

## 4. 准确率怎样算

### 4.1 每天都能看懂的指标

| 指标 | 定义 |
| --- | --- |
| 计划数 | 实验名单×约定应运行的交易日，提前列入台账 |
| 签发覆盖率 | 按时正式签发数 / 计划数；展示未触发、失败、超时 |
| 待核对/不可核对 | PENDING、PENDING_DATA、UNSCORABLE各自计数 |
| 主准确率 | 正确UP/DOWN数 / 已成熟且可核对的正式记录数，实际FLAT也在分母，二选一预测遇FLAT算未命中 |
| 非平盘方向准确率 | 正确UP/DOWN数 / 实际为UP或DOWN的可核对记录数；必须同时展示主准确率和FLAT数量 |
| 上涨/下跌召回率 | 实际上涨/下跌的样本中，各自预测正确的比例 |
| 平衡准确率 | 非平盘样本上涨召回率与下跌召回率的平均；只出现一种实际类别时显示不可计算 |
| 分组表现 | 按证券、日期段、市场方向、协议/模型/方法版本分组；不混合临时实验 |

每个比率显示分子/分母、实际涨/跌/平盘分布、观察时间；不能只给一个漂亮百分比。分类不均衡时普通准确率可能误导，平衡准确率及简单分类器基线的用途可参考[scikit-learn官方评测说明](https://scikit-learn.org/stable/modules/model_evaluation.html)。

### 4.2 简单基线必须一起保存

对同一正式样本、同一标签口径同时比较：

- 永远预测UP。
- 永远预测DOWN。
- 昨日方向延续：按T行情涨跌方向预测；T为FLAT时固定预测UP，规则提前保存。

基线在预测阶段保存，不能事后挑最优阈值或更换规则。若某基线缺输入，比较只在明确的共同样本上进行，主准确率仍保留全部可核对正式记录。

例如行情本身上涨日较多，系统命中率高也可能没有超过永远猜涨。比猜涨多对几次仍需观察不确定性，不能直接宣称有效。

### 4.3 实验周期与版本

首期先运行20个交易日检查数据和流程，继续到60个交易日观察稳定性；这些是试运行节点，不是统计充分性的保证。两只股票60天最多120条样本，同日高度相关，不能当120次独立试验。

不确定性优先按交易日分块重采样评估，保留同日股票相关性；样本太少时只展示描述统计。历史回放按时间分割并审计模型后见知识，真正前瞻结果单独展示。方法/提示/模型版本冻结后评估，修改版本另开实验组，不能边看结果边调参再拿同一段数据证明有效。

预测方向答对、理由有证据、理由后来兑现是三件事。主指标评价方向；原因支持与兑现单独审核。方向正确不能证明模型叙述的因果解释成立。

## 5. 持久化、接口与预算

新增 `NextSessionPrediction`：prediction_id、experiment_id、protocol_id、universe_version、security_id、base_session、target_session、requested_at、evidence_sealed_at、issued_at、input_hash、method/model/prompt_versions、prediction(UP/DOWN)、support_ids、counter_ids、reasons、limitations、review_status、cohort(PRIMARY/EXPLORATORY/COMPARATOR)、supersedes_id。

新增 `NextSessionOutcome`：outcome_id、version、supersedes_id、prediction_id、observed_at、status(PENDING/PENDING_DATA/SCORABLE/UNSCORABLE/CONFLICT)、close、reference_price、return_direction(UP/DOWN/FLAT)、price_source_refs、price_basis、source_hashes、correct、limitations。只有SCORABLE才有return_direction/correct；FLAT的correct为false。

新增 `ExperimentRunSlot`：experiment_id、security_id、base/target_session、planned_window、state(PLANNED/ISSUED/MISSED/FAILED_INPUT/FAILED_REVIEW/TIMEOUT)、prediction_id、reason。即使没有预测成功也有slot，避免只统计成功任务。配置在开始前保存名单、窗口、协议和实际启用的首日；运行时可从配置和交易日历补列截至当前的未触发slot，不需要后台调度。

每次失败尝试追加事件，不覆盖失败痕迹。窗口内失败后重试成功可把slot汇总为ISSUED，但所有attempt、耗时及失败原因仍可查看；第一次成功签发即锁定正式判断。

新接口在 `/api/quant/decision/experiments/next-session` 下：POST runs创建预测批次；GET runs/{id}读取；POST runs/{id}/observe追加真实结果；GET scoreboard按实验/协议/版本返回完整台账和统计。POST observe幂等，官方来源修订时追加结果版本并显示重算原因，原预测保持不变。

统计对每条prediction只取当前有效的结果版本，不重复计分；统计响应保存计算时点、结果版本集合哈希及协议版本。原有统计快照可回看，不能通过选择结果版本展示更好的命中率。

复用存储和内容寻址输入，正式预测有唯一键，客户端不能上传已审核方向或真实标签。批次共享原计划24调用/60,000token/900秒上限；实际发行截止与共享预算取更严格者。默认两标的，不重置每只预算；长研究为另一任务，不要求先完成才能显示预测。新实验默认关闭，用户开启后显示实验范围与实际状态。

## 6. 最早交付及验收

P0固定协议/名单、数据最低要求、类型与12例实验门禁；P1-N做封存快照→真实LLM方向与理由→页面首卡→不可变记录→到期核对→基线统计。首卡取数和审核完成后才显示结论；在运行中显示过程，不先填固定UP。
