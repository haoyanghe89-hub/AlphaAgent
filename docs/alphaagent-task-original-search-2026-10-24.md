# 按任务检索已导入的方法原文

新建投资研究现在会在分析之前检索已导入的方法正文。增强候选筛选、增强市场研究和增强明日研究使用同一套检索器；持仓和组合顾问复用的投资研究也包含这些段落。

## 任务如何形成检索词

增强流程先完成研究规划，再使用本次公开的假设、反证检查、所选规则的标题、关键词和必要输入构成查询。普通投资研究使用公开的研究重点和已绑定方法。私人原始问句、资金、持仓和成本不参与查询。

正文按有重叠的句段切分，使用现有中文双字词和英文分词进行关键词匹配，并为成本、现金流、估值等主题补充有限的中英文关键词。按命中词的稀有度排序，最多提供四段，每段不超过九百字符，同来源族最多两段，并移除相互重叠的命中区间。资料范围为任务创建时已存在的最多两百份资料，每份选择当时可用的最新版本。

检索覆盖规范化后的已导入正文，不受资料的预设锚点或三十条规则的固定引用区间限制。尚未提炼为发布规则的资料也可以被检索。此处的正文范围仍受原始导入内容限制，不能视为已经获得整本书。

## 原文如何进入研究和封存

`original_research` 随公开上下文进入分析、复核和需要它的规划阶段，包含任务查询、检索范围、命中状态、段落原文、作者、来源族、资料版本及字符区间。它单独作为方法参考，不加入公司事实的 `evidence`，不自动变成新的已发布规则。

普通投资研究的报告保存该字段；增强候选和市场研究保存在 `enhanced_research.original_research`；增强明日研究保存在快照的 `model_context.original_research`。投资研究的 audit 接口可以通过 `public_context.original_research` 查看。原来的开发者规则页仍然展示规则自身的固定出处。

`original_search_ref` 指向内容寻址存储中的检索快照。快照记录查询、截止时点、参与检索的资料清单及检索结果；原文、规范化正文和资料清单均纳入任务来源引用。恢复和历史读取会使用这些固定资料重做匹配、校验原文与字符位置，不会改用后来导入的新版本。旧任务没有新的协议标记，按原有流程读取。

没有命中时明确保存 `MISSING` 和空段落，不据此推断原文不存在相关观点。原文损坏、引用被改动或查询与任务不一致时，校验会拒绝将其作为原研究重现。

## 范围与验证

本次没有增加向量模型、向量数据库、模型调用或新依赖。这里提供的是关键词检索和有限词表扩展，不能把它描述为语义检索；换一种说法仍可能漏检。

合成测试覆盖固定锚点之外的内容、尚无规则的资料、不同任务命中变化、引用位置、未命中、未来资料排除、版本更新后的恢复、篡改检测、上下文长度和来源去重，以及多条研究链中实际发送给分析和复核的公开上下文。

对 `docs/knowledge-export/2026-10-20` 的十九份资料进行了只读检索。查询“成本 净收益 换手”命中博格正文的 `[23305, 24172)` 和 `[20031, 20873)`；现有成本规则的固定引用为 `[8089, 8571)` 和 `[11541, 11987)`，证实检索没有被原来的固定引用区间限制。这是检索接入检查，不是回答质量或投资效果评测。

本次验证结果：

- 知识模块、检索观测，以及增强候选、市场和明日流程的回归：`416 passed`，耗时约六分十五秒。
- 新增原文检索与工作流测试单独复验：`9 passed`，包含 audit 查询和核验包中原文、正文、版本清单与检索快照的完整性。
- 修改文件的 Ruff 静态检查及 `git diff --check` 通过。
- 对真实导出资料在三个不同 Python 哈希种子的独立进程中重做检索，完整结果摘要一致。

回归使用合成模型输出，未发起真实模型质量对照。测试生成的 UI 样本保存到 pytest 临时目录，避免写入已有的固定样本路径。
