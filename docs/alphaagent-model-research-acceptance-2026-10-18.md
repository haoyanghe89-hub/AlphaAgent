## 当前一次问题的流程

```text
用户输入股票及期限
  ├─ 解析并核实证券；资金、持仓、股数留在本地
  ├─ 真实读取行情、财报、资金及政策；封存原始响应和基准日
  ├─ 固定请求创建时已发布的知识版本
  │    └─ 当前30条候选规则，保留条件、反例、必需输入及禁止推断
  ├─ Researcher：按证券选择最多3条方法，提出假设与可推翻条件
  │    ├─ 结构化请求 VALUATION_SNAPSHOT 或 EVIDENCE_SEARCH
  │    ├─ Harness核对证券、日期、权限、重复请求和预算后执行
  │    └─ 最多2轮、每轮2个请求；请求、结果与真实调用逐项封存
  ├─ 投资研究：Planner在已准入路线中选择路线
  ├─ Analyst：依据股票事实、选定方法和工具结果给明确方向及反证
  ├─ 程序核查身份、引用、格式、数值边界
  ├─ Verifier：核对事实、期限、条件与方向取舍
  │    └─ 拒绝时回填具体反馈，按原累计预算有限纠错
  ├─ 发布通过版本；本地计算价格条件、仓位、股数和费用
  └─ 页面展示结论、图表与条件；刷新读取原记录，后续按真实行情核对
```

这是模型选择工具、Harness受控执行的结构化循环，没有声称模型已拥有任意网页浏览、任意代码执行或供应商原生 tool_calls 循环。`EVIDENCE_SEARCH` 搜索本次封存证据，当前并不是全网补查。

## 知识和工具边界

- 知识仍为 `REFERENCE_ONLY / UNVALIDATED`。动态选用知识不会改变旧路线入场门槛，更不会把名人观点当作股票事实。
- 研究输入保留必要风险规则；分析投影保留该证券选定的方法、条件和反例。完整知识与工具原始结果仍在封存记录中。
- 估值工具只请求 Tushare `daily_basic` 的指定证券、指定基准日；复核证券、日期、收盘价、字段、原文字节哈希、单位和封存时点。市值保留“万元”，PE/PB保留“倍”。
- 正常无行、空字段和真实来源调用失败分别记录；不填零、不换日、不补造。证券或收盘价错位等完整性错误不会被降级成可用事实。
- 假设与反证检查是可供开发者审阅的产物；不保存供应商隐藏推理文本。

## 推理、预算与恢复

新任务在第一次模型调用前固定推理配置：Researcher、Planner为 low 并留2048推理输出余量；Analyst、Verifier按项目设置采用 high，留8192余量；Writer关闭推理。旧任务继续原配置，已冻结的增强任务也不会在恢复时更换推理身份。

总上限仍为原有24次模型调用、60000令牌、900秒。推理与结构化输出共同使用供应商输出额度，失败和截断都保留实际消耗或最坏预留，不因恢复清零。

中文按UTF-8字节作最坏输入预留，可能在仍有实际额度时过早阻止调用。仅增强任务在这种情况下允许一次**相同模型、消息、schema、推理配置，最多输出1令牌**的计量请求；只有取得有效供应商用量才用精确输入计数保留正式调用。计量自身也计入原上限，未知失败保留最坏扣记。正式调用通过引用、索引、输入哈希和时间顺序绑定计量，不能借计量伪造批准。

投资研究的Writer改为程序逐字发布已批准摘要；旧Writer模型记录仍可读取。明日预测暂保留原Writer调用。明日预测增强协议强制为EXPLORATORY，并按提示、方法、模型等版本单列，旧主实验不变；投资研究也区分新旧研究组。

## 用户点击验收

1. 打开上表三个链接：应直接看到已保存的明确结论、反证和图表；投资研究同时展示等待或触发条件。
2. 按F5：股票、期限、结论和原任务ID应保持，刷新不会重新收费或生成新判断。
3. 展开“支持理由、完整反证与资金政策依据”：核查事实与来源；估值引用如出现，必须显示“倍”或“万元”。
4. 使用页面底部“本页分析与核验”切换开发者入口。投资研究展开“模型分析、工具与公开上下文”并点击读取记录；可查看Researcher假设、工具请求、推理配置、审核和确定性发布状态。
5. 回到首页，在“投资计划”输入另一只股票，或输入任意可核实沪深A股的明日预测问题，生成新的独立记录。原历史不会被新结果替换。
