# AlphaAgent 日常运行与历史保留

## 日常使用速查

### 每天怎么启动

已为当前Windows用户配置登录自启。电脑开机、登录并联网后，后台约15秒后启动；直接打开固定的[工作台](http://127.0.0.1:8839/#/)即可使用，不会自动弹出浏览器。每天09:00另有一次启动检查。无需打开Codex、终端或重新构建前端。

同一个8839服务同时提供后端API和已构建的Vue前端，不需要另开前端开发服务。2026-10-18根据实际重启验收，将系统任务入口改为`pythonw.exe`加`CREATE_NO_WINDOW`，再调用原启动检查脚本；避免Windows默认终端接管PowerShell时弹出常驻窗口。启动诊断保留在`logs/alphaagent-startup.log`，原数据绑定和异常重启继续有效。

需要手动启动时，在PowerShell执行（执行策略只对本次进程生效）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File D:\deepsearch\start-alphaagent.ps1
```

手动脚本会打开工作台，已有正确实例时会复用。再次打开网页可直接使用这个固定地址，无需任何阶段、review或developer参数。

希望看当日盘前清单，建议09:00—09:10前登录Windows，保持电脑联网、运行且不休眠。关闭网页不影响后台；重启后登录会再次自动启动。电脑关机、休眠或用户尚未登录时，本地服务不能执行盘前工作。盘前准备、自动核对和行情后台更新不依赖浏览器一直打开。

### 系统自动做什么

时间均为北京时间，盘前与收盘日程按交易日历运行。任务耗时、数据异常或正在进行的用户研究可能使后台工作顺延，以下频率不是数据供应商的实时性承诺。

| 内容 | 运行时间／频率 | 你能看到什么 |
| --- | --- | --- |
| 指数、行业热点与行业代表股 | 可见页面约每30秒读取；行业后台交易时段约30秒，其他时间约10分钟尝试更新 | 首页报价、行业涨跌、成交热度和代表股，分别标明报价时间 |
| 所选股票主力资金分钟监控 | 首页可见时约每30秒读取 | 所选股票的分钟资金及价格曲线 |
| 行业与个股盘后资金榜 | 约每10分钟尝试更新 | 最新可得交易日的大单／特大单口径资金榜，不当作全市场盘中资金 |
| 盘前行业关注清单 | 交易日09:10开始准备，09:25起展示已审核内容 | 4–6个重点行业、理由、确认条件与反证；使用上个完整交易日资料，自动保存每日清单 |
| 已保存明日预测的真实核对 | 15:40、18:10两个检查窗口；启动时补查此前应核对的记录 | 真实结果、命中情况及简单基线；未到期、停牌、缺数和冲突分别标注 |
| 支持跟踪的投资研究后续观察 | 按上述后台核对机制执行 | 后续真实行情、条件观察及到期方向核对，原报告继续保留 |
| 本地完整备份 | 每天21:00；登录后约2分钟检查并补做错过的备份 | SQLite、原文、旧报告、知识版本与本机配置的独立快照；同一日程窗口不重复备份 |

休市时保留最近交易日数据。先看“报价时间／数据日期”，再判断数据是否适用于当前问题；“刚刚读取”不等于“刚刚成交”。盘前清单展示的是关注行业与条件，交易由你决定。当前没有每天自动为所有股票新建预测、计划或账户建议的日程。

### 需要你手动操作什么

1. **提出新研究。** 从首页选择明日预测、投资计划、未来三个月、市场观察、行业候选、持仓顾问或账户调仓，输入股票或问题。进入资料表时确认股票、周期及所需字段，再点击生成。
2. **更新账户资料。** 成交、加减仓、资金转入转出后，填入最新现金、成本、股数、可卖股数与今日买入股数。系统按你本轮声明的资料计算；账户与券商成交记录需要你同步。交易在券商端由你执行。
3. **主动取得新判断。** 行情会刷新，旧报告使用的原输入和建议保持不变。需要今天的新结论时重新提问；持仓／账户页需要重取公开资料时勾选对应更新选项，再提交新一轮。只修改输入、尚未提交时，不会生成新结果。
4. **查看结果与历史。** 先读结论和操作条件，再看图表；完整理由与反证可展开。[历史库](http://127.0.0.1:8839/#/library)可按功能、状态和关键词筛选。每次正式生成或追问另存，保留原轮。
5. **补充知识材料。** 把值得参考的书籍、政策原文或博主观点发来分析，按候选、审核、固定版本发布流程补充知识。已审核知识不随每日行情自动改写。
6. **检查备份与处理异常。** 本机每天自动备份，重要研究后也可手动补做，步骤见本文“备份与迁移”。建议定期将成功备份另存到外置盘，防范整块D盘损坏。页面显示异常时先保留原任务，从原记录刷新或恢复；持续失败时保留提示、股票与任务ID用于排查。

### 正常状态与历史位置

[开发者工作区](http://127.0.0.1:8839/?developer=1#/developer)可检查“服务ok／每日更新已开启”；数据通道或日程异常以当前页面状态为准。普通用户日常从工作台使用即可。

活动历史目录是`D:\deepsearch\.phase3-quant-o\alpha-history-real-02`。其中`metadata.sqlite`和`blobs`配对保存研究与原始资料；目录名虽然来自早期开发，它现在承担正式历史存储，必须完整保留。备份还需保留本机配置、知识版本指针和私下保存的密钥配置。

日常节奏可以是：盘前启动并查看关注行业 → 盘中按需提问、查看资金与条件 → 成交后更新账户资料 → 盘后查看真实核对与历史。

## 当前入口

Windows登录后由`AlphaAgent-Service`任务自动启动，浏览器统一访问 `http://127.0.0.1:8839/#/`。手动运行`start-alphaagent.ps1`也会核对已运行实例的数据目录并复用服务。关闭浏览器不会停止后台服务；重启后登录会自动恢复后台。

`alphaagent.local.json` 是本机配置，已绑定原 `.phase3-quant-o/alpha-history-real-02` 数据目录和8839端口。目录名来自历史开发，但它现在是持续使用的活动库；不要按“阶段临时文件”清理。脚本发现数据库或原文目录缺失会报错，不会另建空库。

工作台提问生成新的独立研究；完整结果和原输入留在 SQLite／CAS。`#/library` 跨功能分页、搜索全部已登记研究，打开旧ID仍读取当时封存的结果。行情刷新、观察核对只追加记录，不覆盖原预测、资金画像或计划。页面不需要每轮开发使用新的 `review=` 链接。

明日预测、投资计划、单股持仓顾问与账户调仓已完成 [真实页面全流程检查](superpowers/plans/2026-10-17-alphaagent-system-e2e-results.md)。短暂连接失败会自动重连同一任务；提交回执丢失时按原请求标识确认，避免重复生成。通道繁忙时最多等待约一分钟，输入与上轮结果保留；继续繁忙会明确提示，可稍后重试。原文或版本校验失败仍隐藏结果，不能用重试绕过。旧档案列表异常不再挡住统一历史库的读取和搜索。

日常页面统一先看结论、关键数字和操作条件，再看图表与可展开依据。已有报告上方的资料区默认收起；展开后可更新本次输入，原历史不会覆盖。历史库支持研究类型、状态及文字筛选。内部定向取证和历史数据检查在开发者历史库保留，原链接仍可回看。

右上角“开发者”进入 `http://127.0.0.1:8839/?developer=1#/developer`，查看服务状态、知识核验、数据接入和完整历史。报告页脚“本页分析与核验”保留原ID切换展示，“返回用户视图”回到同一结果。该参数仅控制展示，不授予额外发布或交易权限。旧5.2回测仍需完整历史数据包通过准入；数据受限时明确说明原因，用户页不铺满空收益表和空图。

## 每日服务

- 首页前台每30秒刷新报价和所选股票分钟资金；服务后台在交易时段每30秒刷新行业行情，休市每10分钟尝试更新。盘后主力资金每10分钟更新。报价时间、数据日期及读取时间分别展示，旧缓存不能伪称当前行情。
- 每个交易日09:10开始准备行业关注清单，09:25在首页展示通过审核的版本。开盘前迟启动会按实际时间生成；09:30后没有开始的日程记为错过，不回填早于实际时间的推荐。
- 首版给4–6个重点行业，使用上个已完成交易日的共同窗口及已审核知识，依次经过 Planner、Analyst、Verifier、Writer。它没有假称包含今日最终集合竞价、新新闻或新政策。WATCH是关注，WAIT是等待，均不表示已满足个股入场条件。
- 当前观察按钮按实际时间生成，同日复用同一清单；不会计为准时盘前样本。清单、数据、方法版本、模型输入输出及计费均保留。恢复复用已完成步骤，不重置已耗预算。
- 自动核对在15:40、18:10两个窗口有界执行，启动时补查以前已收盘而尚未核对的记录。研究在执行时后台核对让出容量；每次处理一条，持久化记录防止重启后重复执行同一窗口。未到期不填结果，缺数、停牌、失败和修订另存，既有成绩不覆盖。

电脑需在09:10前开机、登录并联网。Windows任务负责启动常驻Python服务，行情、盘前和核对日程在服务内部执行，不依赖本聊天或Codex定时任务，也不自动交易。用户提问仍是单股预测和投资计划的生成入口。

## 数据连接与覆盖

2026-10-17早间的Tushare HTTPS证书错误已于09:49严格复测恢复。随后真实读数取得行业目录、成分、日线和盘后资金；没有关闭TLS校验、明文发送Token或改用不明镜像。当前无需为本次已验证接口重新购买权限或更换密钥。

首页运行状态来自正在运行的服务，K7交付页的封存健康记录只描述当时验收。日后供应商中断时保留上次成功快照及原时间，按有界周期重试；不能承诺外部服务永不中断。

首份行业观察读取31个申万一级行业与固定成熟上市成分池。14个行业的二十日共同窗口完整，17个行业因部分成员缺数未参与本次推荐。未缩小分母冒充完整行业排序，也未以零填缺项。这是当次有覆盖声明的关注清单，不是全市场最优行业证明。首页完整的当日行业涨跌榜与这份共同窗口研究的口径不同。

交易日必须来自有来源的日历，不能只按周一至周五推断。下一交易日旧实验的公告解析和注册配置目前核定至2026年；跨年须依据新年度交易所公告发布新实验配置，旧日历与成绩保持不变。每日运行服务有独立的提供商日历入口，可供后续年度接续。

## 备份与迁移

已配置`AlphaAgent-Backup`任务，每天北京时间21:00备份；若错过，Windows可在可运行时补做，登录后约2分钟也会检查。最近一次成功备份已覆盖当前日程窗口时会跳过，避免重复。备份失败保留上次成功版本并记录失败；任务最多重试3次，每次间隔2分钟。不会自动删除历史或旧备份，磁盘空间不足时停止新备份。

备份保存在`D:\deepsearch\backups\alphaagent\日期时间-唯一编号\`，与活动历史目录分开。每个完整快照包括：

- `history/`：在线SQLite快照、数据库引用的原文及配对校验清单。
- `runtime/data/`：旧报告文件、调用日志、知识／研究版本指针及其他活动目录文件。
- `runtime/unreferenced-blobs/`：未列入数据库引用图的其他已有CAS原文。
- `config/`：本机数据路径配置、启动脚本及`.env`的本地副本。
- `bundle-manifest.json`：上述补充文件的SHA-256校验清单。

备份目录仅向当前Windows用户、SYSTEM和管理员开放，含密钥、可能填写的资金与持仓资料，请勿把整个目录发到聊天或分享给他人。当前备份与活动库同在D盘，能帮助恢复误操作，不能防范整块磁盘损坏；外置盘或异机副本需要你另行保存。备份不是程序安装包，迁移仍需项目代码与Python运行环境。

在`D:\deepsearch`的PowerShell中手动立即备份／校验（校验时替换为真实目录）：

```powershell
.venv\Scripts\python.exe scripts\backup_alphaagent.py
.venv\Scripts\python.exe scripts\backup_alphaagent.py --verify backups\alphaagent\日期时间-唯一编号
```

`last-run.json`记录最近运行状态，`last-success.json`指向最近成功且通过校验的备份。任务状态可在Windows“任务计划程序”中查看`AlphaAgent-Service`和`AlphaAgent-Backup`；服务任务长期显示“正在运行”是正常情况。也可运行：

```powershell
Get-ScheduledTask -TaskName AlphaAgent-*
Get-ScheduledTaskInfo -TaskName AlphaAgent-Backup
Get-Content D:\deepsearch\backups\alphaagent\last-success.json
```

安装脚本是`D:\deepsearch\install-alphaagent-tasks.ps1`，绑定当前登录账户，无需保存Windows密码；重复安装只更新本项目自己的两项任务。更换Windows账户、项目位置或备份盘时，在目标账户重新运行安装脚本，保留原历史路径。任务的执行策略仅作用于启动进程，没有修改系统执行策略。可在任务计划程序中禁用上述两项任务来取消自动运行，原数据与备份继续保留。

恢复前先完整校验备份，在全新目录执行隔离恢复演练，核对数据库、原文、知识版本、旧报告和历史ID。恢复会保留隔离标记，未完成对账前不启动研究执行器，不自动替换当前活动库。`history/`的配对恢复工具不负责补充文件：还需按完整备份清单恢复`runtime`，并核对配置中的实际路径；不能只恢复数据库或直接把恢复演练目录作为正式目录。

服务入口为 `scripts/serve_alphaagent.py --data <已有活动目录> --port 8839`，业务日程在Python服务内部运行，Windows任务只负责本机启动与备份。因此后续可移到常开服务器，继续使用相同数据库、CAS和历史ID。迁移应先完整备份、隔离恢复与核验、对账，再切换活动目录；恢复演练的隔离标记不能直接绕过。当前继续绑定回环地址，未来远程访问可先用安全隧道，公网多用户访问另行建立认证。

## 可靠性边界

公开模型上下文不包含账户、资金、持仓、股数或Token。知识补充仍走候选与审核，方法效果未经验证。旧5.2正式回测门禁不降低。原报告版本是历史出处，不是日常应用的多个独立版本。


持仓顾问现已接入统一工作台与历史库，输入、隐私和追问规则见 [持仓顾问](alphaagent-holding-advisor.md)。原有每日刷新、盘前清单和到期核对继续运行。

多只持仓请使用工作台“账户调仓”，结合完整账户现金、行业与收益相关性生成整体安排，见 [账户调仓](alphaagent-portfolio-advisor.md)。它与单股顾问共用原数据库和知识体系，各轮分别保存，旧历史继续保留。
