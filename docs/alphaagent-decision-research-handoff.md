## 2. 已确定的方向，执行者不必重新询问

- 从资料汇总升级到解释经营、行业、价格及资金变化，形成有依据、有反证和失效条件的研究判断。
- 两个期限分别建设：下一交易日UP/DOWN实验；未来1–3个月的经营、行业、预期差、资金和龙头候选研究。长期看好不能自动推导为明日上涨。
- 第一条行业闭环使用半导体设备，制造端用于核查需求，封测后续独立扩展；不再以家电作为新能力首发行业。中微公司和北方华创是验收样本，不是产品写死的支持名单或已确认推荐。
- 热点有时效性。部署时重新取数并说明覆盖范围，不把2026-10-09的开发选题线索当作今天全市场最热的证明。
- 保留deepsearch后端底盘、Vue 3、Multi-agent、现有原型样式及浅色/深色切换；保留旧单股、DCF、K线、双股比较、历史及策略功能。
- 免费来源优先。数据缺项可以按能力降级并预留接入口，但不能用假数据、固定演示值或假“实时”补齐。
- Codex负责资料筛选、方法提炼和审核，不要求用户先找资深投资专家。不微调作为首版前置，也不建立“名人Agent投票”。
- 数字由确定性工具计算；原型计算代码不可移植。自算值要做手算样例、同输入复算和有明确口径的独立参考核对。
- 资金中的成交活跃、供应商大单估算、融资变化、ETF份额、真实订单流是不同对象；不能相加成“主力资金”，也不能据此虚构机构意图。
- 原5.2真实全市场历史资料与全收益独立核对缺口仍保留，新增功能不能绕过正式回测门禁。
- 首版不输出未经校准的概率，不自动交易，不创建定时任务。阶段自测后交给用户在真实页面点击验收。

## 3. 开发顺序和第一个可验收成果

执行顺序：**P0 → P1 → P1-N → P2 → P3 → P4 → P5 → P6 → P7**。这些是本轮新能力的任务编号，不等于旧项目5.2/5.3编号。

| 阶段 | 必须交付什么 |
| --- | --- |
| P0 | 核对现有能力；探测真实来源；建立方法卡、合同、实验配置和48例评测清单 |
| P1 | 单股定向取证、数字与文本证据、最小可演示报告 |
| P1-N | 封存输入→真实模型预测涨/跌及理由→审核→保存原判断→页面首卡→次日核对→准确率和基线看板 |
| P2 | 经营及预期差、有限补证循环、1–3个月情景和首次前瞻台账 |
| P3 | 不同口径资金指标、交叉核查、解释和原型风格图表 |
| P4 | 行业传导、事件与价格变化的竞争解释 |
| P5 | 有证据的龙头候选、排除原因、条件化意见和同业比较 |
| P6 | 明确覆盖范围的市场扫描、手动刷新、观点变化和历史版本 |
| P7 | 统一功能门禁、真实模型及浏览器验收、消融比较和交付记录 |

最早可演示的完整闭环是P1-N，不等待整个市场扫描建成。默认两证券固定篮子、交易日20:00–20:15签发；非窗口运行另列探索组。用户可以在首卡看方向、支持理由、反面证据和截止时间，然后查看不可修改的原判断。

P1-N软件验收分两次：先验收真实取数、模型签发、封存和页面；等目标交易日实际收盘后，再验收真实标签、命中和统计。开发夹具能检验功能，但不能代替真实隔日结果。20/60交易日是观察节点，不是功能开发必须等待的时长，也不是预测有效的证明。

实验实际FLAT在主准确率中算未命中；停牌等不可核对单列，失败、漏跑和待核对也保留；永远涨、永远跌、昨日延续基线必须一起展示。版本和时点改变分组，不能事后挑选最好的预测。

48例门禁由24例基础、12例领域、12例日预测实验组成。功能通过、原因有依据和真实预测是否优于基线，是三种不同的验收结果。
